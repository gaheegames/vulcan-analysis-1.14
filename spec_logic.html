시스템 규칙 (1.13.14 코드 기준)

원본 저장소의 1.13.14 C# 소스에서 수식·상수·제한을 뽑았습니다. APK 1.14.0.1에는 메서드 본문이 없어서 1.14의 실제 로직과 다를 수 있습니다.

  • 기준: GitHub vulcan-RPG/VULCAN-CLIENT 경로 260326_1.13.14_VULCAN/Assets/@@Scripts/ (커밋 27c2368)
  • 출시 APK는 1.14.0.1(IL2CPP)이므로 모든 항목은 "1.13.14 코드 기준". 1.14에서 바뀌었을 수 있음.
  • 근거 표기: 파일:라인 (경로는 Assets/@@Scripts/ 이하). 라인은 MCP로 받은 원문 기준 실제 라인.
  • 표기 규칙: = 코드에 문자 그대로 있음 / 추정 = 코드 해석·이름·호출 관계로 미루어 본 것.
  • 수치 데이터(아이템 스탯, 몬스터 HP, 강화표 등 ScriptableObject 값)는 범위 밖. 여기서는 "값을 어떻게 쓰는지"와 "코드에 박힌 상수"만 다룸.
  • 열람 파일 68개 + 디렉터리 목록 약 47회. 영웅 스킬 스크립트는 13종 중 3종(로더·카이라·드렉스)만 열람.

1. 전투 공식 (데미지·치명타·공속·방어)

규칙 요약

  • 방어 공식은 피해 × 4000 / (4000 + 방어력). 물리(p)는 p_DFS, 마법(o)은 o_DFS 적용.
  • 일반 공격 1발 피해 = 공격자 ATK의 100%. 치명타 판정은 Random(0,100) < cri, 치명 시 피해 × cri_ATK/100 (cri_ATK는 % 배율, 150이면 1.5배).
  • 공격 쿨다운 = 1 / ATK_Speed 초 (ATK_Speed = 초당 공격 횟수).
  • ATK는 직업이 메이지면 o_ATK, 그 외는 p_ATK. 어떤 방어를 적용할지는 공격 타입(atk_type)이 정하며 ATK 출처와는 별개. 예: 로더 '데스 마크'는 p_ATK 기반 ATK로 마법(o) 판정 탄을 쏨.
  • 세트효과 Plus_ATK는 공격자 쪽 피해 증가(dmg += dmg × Plus_ATK). Plus_ODFS·Plus_PDFS는 피격자 쪽 피해 감소율.
  • PVP·길드아레나 씬 보정: 받는 피해 ×0.7, ATK ×0.6, 치명 배율 100 + (cri_ATK−100)×0.6, 최대 HP ×2.5.
  • 몬스터의 치명 피해는 ATK × cri_ATK(나누기 100 없음)로 플레이어 탄환 공식과 다름.
  • PVP 타깃 우선순위: 팔라딘 > 워리어 > 메이지 > 헌터 > 어쌔신 순, 같은 직업 안에서는 가까운 순. 몬스터도 플레이어를 같은 순서로 노림.
  • ⚠ 버그 의심 플레이어 피격(Character.GetDamage)은 물리·마법 모두 (1 − Plus_ODFS)를 곱하므로 루나 세트(PDFS)는 플레이어 피격 감소에 쓰이지 않음. 몬스터 피격은 마법→Plus_PDFS, 물리→Plus_ODFS로 교차 적용.
  • ⚠ 버그 의심 Player.AOE와 팔라딘 R 스킬은 치명 계산값(finalDamage)을 만들고도 GetDamage에는 m_DMG(비치명)를 넘김. 결과적으로 치명이 적용되지 않음.

2. 스탯 합산 순서 (영웅 최종 능력치)

규칙 요약 (Player.Data_Set 호출 순서)

  • 기본+벨트: Character_Scriptable 기본값 + 벨트 옵션(고정값: HP·ATK·O_ATK·DFS·o_DFS·Cri·cri_ATK). 공속·이속은 기본값 × 벨트% 가산.
  • 레벨 성장: (등급별 Grad_Stats.g_* + 직업별 Job_Stats.j_*) × 레벨. HP·p/o_ATK·p/o_DFS만 해당.
  • 주사위 스탯(Stats_Mng): 슬롯별 고정값 합산. 공속·이속은 % 가산.
  • 장비(강화 포함): 고정값 합산. 공속·이속은 현재값 대비 %.
  • 코스튬: 장착 코스튬의 Type이 "s"이면 지정 스탯 +Value%.
  • 각성: AW당 HP +2%, p/o_ATK +3.5%, p/o_DFS +1%.
  • PVP면 HP ×2.5, 마지막으로 SetAttackPower(ATK 결정, PVP 보정).
  • 마을·칭호·상점 버프는 전투 스탯에 관여하지 않음. 골드·경험치·제작에만 쓰임(5·11·12절).
  • 초월(TC)은 Player 스탯 계산에 쓰이지 않음. 값은 읽어오지만(Player.cs:405) 실제 효과는 영웅별 스킬 스크립트에서만 처리(3절).
  • 추정 코스튬 ATK% 분기는 ATK를 직접 올리는데, 직후 SetAttackPower가 ATK를 p/o_ATK로 다시 덮어쓰므로 사실상 무효로 보임.

3. 영웅 성장 (레벨·등급·초월·각성)

규칙 요약

  • 레벨 상한 40. 40 초과 감지 시 치트 처리("레벨조작"). 남는 경험치는 다음 레벨로 이월, 40 도달 시 경험치 0.
  • 경험치 보너스 = round(획득EXP × (상점EXP + 호박EXP + 코스튬EXP + 길드아레나3 + 마을E_buff + 길드장버프 + 칭호EXP) / 100). 모든 버프가 합연산.
  • 처치 경험치는 몬스터의 '현재 타깃' 플레이어 1명만 받음(분배 없음).
  • 등급업(C→R→E→RD)은 영웅 조각(=중복 획득 수, C) 소모. 현재 등급 기준 필요량 C 50, R 600, E 1800. RD는 더 오를 등급이 없음.
  • 초월: RD 전용, 1회 조각 300, 최대 20. 효과값 TC × 2.5(영웅별 해석은 아래 표).
  • 각성: RD 전용, 1회 조각 250, 최대 50. 스탯은 2절 6단계.
  • UI는 count + 1 >= 필요량으로 버튼을 열지만, 실제 처리(Character_Mng)는 C >= 필요량일 때만 진행(1개 차이).
  • 스킬 해금 = 영웅 등급 ≥ 스킬 등급. 스킬 피해 = ATK × Skill_Dmg / 100. 쿨 = Cool × (1 − 세트 쿨감).

  • 완료 판정은 Random(0,100) 소수 1자리 반올림 ≤ Item_Chance + 칭호 제작확률버프 이면 성공.

  • 즉시완성(O_Item #5): 정수류(회복·흡수·헌터·워리어·어쌔신·메이지의 정수)와 오래된 곡괭이는 70개, 그 외 등급별 C1 / R5 / E30 / RD70. 남은 시간이 전체의 50% 미만이면 절반(반올림).

6. 장비 강화 (Enhance)

규칙 요약

7. 가챠 (영웅 소환 / 아이템 상자 / 이벤트)

영웅 소환

  • 비용은 Gacha_Scriptable.Number(O_Item) × Count. 서버 인벤을 다시 조회해 재검증한 뒤 차감.
  • 1회 소환 = 영웅 1명 결정 + 조각 지급. Count 30 → 조각 20, 80 → 50, 150 → 100, 200 → 100.
  • 추첨 방식이 '가중치'가 아니라 '임계값': rv = Random(0,100), Chance ≥ rv인 항목 중 (Chance − rv)가 가장 작은 항목. 해당 없으면 재추첨.
  • 결과적으로 항목 i의 실효 확률 = (c_i − 바로 아래 Chance) / max(Chance). 같은 Chance끼리는 확률을 나눠 가짐.
  • 추정 데이터의 Chance를 개별 확률로 해석하면 오해가 생김. 누적 경계값으로 읽어야 함.
  • 천장(pity) 코드 없음(GachaSystem·UI_Gacha_Check 범위).
  • 직업 픽업 소환(메이지·어쌔신·워리어·팔라딘·헌터) 별도 테이블 존재.

아이템 상자

  • I_Data.Count < 50이면 20개, > 50이면 80개 지급. ⚠ 버그 의심 정확히 50이면 아무 분기도 타지 않음.
  • 각 아이템을 리스트 순서대로 돌며 Random(0,100) ≤ Chance면 획득. 목표 개수를 채울 때까지 반복.
  • 추정 리스트 앞쪽(Common)이 먼저 순회되므로 표기 확률보다 유리하게 뽑힘.
